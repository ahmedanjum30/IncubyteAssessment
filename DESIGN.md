# DESIGN.md

UI/UX rules for the Salary Management app.

## Mandatory process

All design work **must** be done with the two design skills available in this environment:

1. **`impeccable`**: design, critique, polish, accessibility and design-system capture.
2. **`ui-ux-pro-max`**: styles, palettes, font pairings, UX guidelines, chart types and stack-specific (Next.js) guidance.

Before creating or changing any screen, component, layout, color, typography, chart or interaction:

- Load both skills.
- Use them to choose and justify the decision.
- Record the resulting decisions (tokens, components, patterns) in this file so later work stays consistent.

No ad-hoc styling outside the decisions recorded here.

## User and context

- **Persona:** HR Manager at ACME.
- **Job:** manage salary records for ~10,000 employees across multiple countries, and answer questions about how the org pays people.
- **Nature of the UI:** a data-dense internal tool. Clarity, scannability and speed matter more than decoration.

## Design decisions

_To be filled in using `impeccable` and `ui-ux-pro-max` before the first UI commit:_

- Visual style
- Color tokens (light and dark)
- Typography
- Component library
- Layout and navigation
- Data table patterns (search, filter, sort, pagination for 10k rows)
- Forms and validation patterns
- Charts for salary insights
- Accessibility baseline
